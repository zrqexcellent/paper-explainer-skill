## 1. 目录页

### 内容

- 论文标题（大号字体）
- 论文元信息：作者、年份、机构、发表场所
- 一句话概括论文核心贡献
- 所有 section 的导航卡片列表，每张卡片包含：section 编号、标题、简短描述

### 交互

- 卡片 hover 时向右平移 4px + 边框变蓝 + 阴影
- 点击跳转到对应幻灯片
- 底部显示统计数字（幻灯片总数、核心技术数量、交互演示数量）

### 设计参考

参考 learn-ai 的 `index.html` 和 `llm-story.html` 的目录页风格：左栏放标题和统计，右栏放章节卡片列表。

## 2. 论文背景

### 内容结构（左栏 + 右栏）

**左栏**：
- 论文基本信息卡片（作者、年份、机构）
- "为什么需要这篇论文？"（2-3 句概括核心问题）
- 前人方案的局限（列表形式）

**右栏**：
- 可视化展示前人方案的问题（步骤推进式或对比式）
- 如果有历史演进数据，用时间线或统计卡片展示

### 交互建议

- **步骤推进**：逐步展示"前人方案 A → 方案 B → 都不行 → 需要新方案"
- **VS 对比**：如果只有 2-3 种前人方案，用 VS 双栏对比

## 3. 核心机制（重点 Section）

这是最重要的 section，可以拆分为 1-3 页幻灯片。每个核心技术概念一个页面。

### 四层内容结构

**每个核心机制必须包含**：

1. **专业定义**（左栏上方）
   - 准确的技术定义，1-2 句话
   - 使用徽章标注所属类别

2. **通俗讲解**（左栏中部）
   - 使用 analogy 卡片（amber 色左边框）
   - 用日常生活中的例子解释这个概念
   - 格式：先给出类比场景，再映射回技术概念

3. **交互图示**（右栏，占页面 60%）
   - 根据概念类型选择交互方式（见下表）

4. **实际案例**（左栏下方或右栏底部）
   - 具体的应用场景或数据
   - 用 tip 绿色卡片呈现关键结论

### 交互方式选择表

| 技术概念类型 | 推荐交互 | 适用场景举例 |
|-------------|---------|------------|
| 数据流转/处理流程 | 步骤推进（左步骤 + 右动画） | 训练流程、推理流程、RAG 流程 |
| 多种方法对比 | Tab 切换 + 可视化 | CNN vs RNN vs Transformer、不同注意力类型 |
| 概率分布/参数影响 | 滑块 + 实时更新 | Temperature、Top-P、学习率 |
| 架构/组件关系 | 流程图（flow-node） | Encoder-Decoder、Agent 架构 |
| 文本生成/序列 | Token 链 + 概率条 | Base 模型、自回归生成 |
| 对话/问答过程 | 聊天气泡（user/AI） | Prompt Engineering、幻觉演示 |
| 方案对比 | VS 双栏（bad/good） | 有 RAG vs 无 RAG |
| 多维数据 | 统计卡片 + 进度条 | 模型性能对比、成本分析 |

### 通俗讲解（Analogy）写作规范

好的 analogy 示例：
- "想象你在读一本小说，RNN 就像一个逐字阅读者——必须先读完第 1 页才能读第 2 页。"
- "KV Cache 就像你读书时在书页边缘折角做标记——下次翻到这页时不用重新读。"

差的 analogy（避免）：
- "Attention 就是 QKV 矩阵乘法"（这还是技术语言）
- "就像机器学习一样"（太抽象）

规则：
- 用日常生活场景（读书、购物、开会、做饭、导航）
- 先描述类比场景 2-3 句，再一句话映射回技术
- 每个核心机制页面恰好 1 个 analogy，不要堆砌

## 4. 整体架构

### 内容

- 架构总览图（所有组件的位置和关系）
- 数据流走向（从输入到输出的完整路径）
- 各组件的一句话职责

### 交互

- 使用 **流程图**（flow-node）布局
- 点击某个节点高亮并在下方显示详细说明
- 用箭头连接表示数据流方向

### 设计

参考 learn-ai 的 RAG 页面（`1-2-mitigation-rag.html`）的 flow-view 模式：
- 上方横向排列核心组件节点
- 下方纵向展示数据流
- 当前激活节点有蓝色边框

## 5. 设计原理

**目标**：揭示"这个方案是怎么被想出来的"。

### 内容框架（三段式）

**第一段：前人的思维定式**
- 这个领域之前的主流做法
- 前人做法的根本假设
- 这个假设的隐蔽代价

**第二段：作者的关键洞察**
- 作者打破了什么假设？（用金色大字呈现）
- 为什么这个洞察在当时不显而易见？
- 可能的灵感来源（合理推测，标注 `[推测]`）

**第三段：从洞察到方案**
- 从关键洞察到最终方案的推导链
- 方案中的"做减法"决策（去掉什么比加上什么更重要）
- 最反直觉的设计选择及原因

### 交互

- **步骤推进**：左栏 3 个步骤（定式→洞察→方案），右栏对应 3 张卡片
- 洞察步骤用 mantra 金色宣言卡片突出显示

### 设计

参考 learn-ai 的 `engineering-philosophy.html`：
- 左栏步骤逐一出现（opacity + translateX 动画）
- 右栏卡片随步骤切换（display + opacity + translateY 动画）
- 核心洞察用金色渐变背景的宣言卡片

## 6. 产品洞察

**目标**：从顶尖产品经理视角提炼可行动的洞察。

### 内容框架（三层递进）

**第一层：抽象设计原理表格**

在左栏放一个表格，提取 3-5 个可迁移原则：

| 技术概念 | 抽象原理 | 产品类比 |
|---------|---------|---------|
| 自注意力 | 动态权重分配 | 个性化推荐根据意图调权重 |
| 多头注意力 | 多维度审视 | 决策评审引入多个角色视角 |
| 位置编码 | 信息结构化 | 给无序信息加上层级标记 |

**第二层：产品机会分析**

在右栏用场景卡片展示：
- 卡片 1：**UX 重构** — 这项技术如何改变用户交互方式
- 卡片 2：**技术选型** — 产品经理需要关注的技术决策点
- 卡片 3：**竞争格局** — 这项技术对行业竞争的影响
- 卡片 4：**风险局限** — 这项技术的边界和潜在陷阱

点击每张卡片，右栏下方展开详细分析。

**第三层：行动建议**

用绿色 tip 卡片列出 2-4 条可立即执行的建议：

- **[动词短语]**：具体描述 + 为什么重要

### 交互

- **场景选择**：左栏 4 张场景卡片（UX/技术/竞争/风险），点击切换右栏内容
- 每张卡片带不同颜色的 badge

### 设计参考

- 场景卡片参考 learn-ai 的 RAG 页面（`1-2-mitigation-rag.html`）的 scene-card 模式
- 行动建议参考 learn-ai 的 tip 组件

## 7. 总结与影响力

### 内容

- **一句话贡献**：用金色大字呈现论文最核心的一句话贡献
- **后世影响**：哪些后续工作直接受此论文启发（时间线或列表）
- **架构总图**：一张完整的架构图作为视觉收尾

### 交互

- 步骤推进：先展示"一句话贡献"宣言 → 展示"后世影响"时间线 → 展示"架构总图"
- 架构总图用 SVG 绘制，关键组件可 hover 查看说明

### 设计

- "一句话贡献"用 mantra 金色宣言卡片
- 后世影响用带时间轴的步骤列表
- 整体使用 engineering-philosophy.html 的左右分栏 + 步骤切换模式

## 质量检查清单

生成完成后，逐项检查：

- [ ] 每页是否都是 16:9 aspect-ratio 的 `.slide` 容器？
- [ ] CSS 变量是否统一使用 `--bg: #f7f5f0` 等标准色板？
- [ ] 是否使用了系统字体栈（不引入外部字体）？
- [ ] 左讲解 + 右交互的双栏布局是否正确？
- [ ] 每个核心机制页面是否包含四层内容（定义+通俗讲解+交互图示+案例）？
- [ ] analogy 通俗讲解是否使用了日常生活场景？
- [ ] 设计原理 section 是否使用了三段式框架？
- [ ] 产品洞察 section 是否包含抽象原理表格 + 场景分析 + 行动建议？
- [ ] 动画是否使用了 `.show` 类触发？
- [ ] 是否注入了 `nav-inject.js` 并更新了 `SLIDE_ORDER`？
- [ ] 所有页面标题是否包含 `| xueai.app` 或类似的品牌标识？（可选）
- [ ] 响应式适配是否包含横屏/竖屏处理？
